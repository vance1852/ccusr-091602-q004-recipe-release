# 工艺配方受控发布平台

管理制造配方从编辑、复核到设备生效的受控过程，解决"同名配方在研发库、
MES、机器人控制器各有一个版本、操作员选错参数导致整批报废"的问题。

- 配方内容、审核签名、设备指令/回执分离保存；
- 发布记录只持有 **SHA-256 内容摘要**，内容对象不可变；
- 外部消息（审核、指令、回执、授权）一律携带原始 `alg` / `kid` / `sig`
  字段，使用 HMAC-SHA256（HS256）签名，验签使用恒定时间比较。

## 受控全流程

```
工艺工程师编辑草稿
   │  提交时执行：量纲校验 + 全局范围 + 设备无关依赖 + 跨参数关系
   ▼
technical_review ── 审核人禁止批准自己提交的变更
   │
   ├─ 含高风险参数 ─▶ quality_review（质量负责人会签；同样禁止自签）
   ▼
approved ──创建发布──▶ frozen（冻结内容摘要、设备能力预检、确定波次）
   ▼
deploying：按设备组分波下发（默认 canary 试点组最先）
   │  每台设备：平台签名指令 → 控制器验签 → 回执签名 → 平台验签/核摘要/防重
   ├─ 当前波全部 applied ─▶ 才允许扩散下一波（灰度门控）
   ├─ digest_mismatch / timeout / rejected ─▶ paused，立即停止扩散
   │     · 已 applied 的设备继续标记当前版本
   │     · 可重试单台（控制器恢复）后 resume，或回滚
   ▼
completed
   │  异常时
   ▼
rolled_back：原发布失效（不删除、不覆盖），另创建一个引用旧内容摘要的
             新发布，沿同一灰度流程重新下发，默认只面向已受影响设备
```

开批授权（`Authorizer`）在开批前核验：设备×产品存在**唯一**适用版本、
令牌签名有效、未过期、未撤销、引用的发布与摘要仍为当前版本。灰度外设备
在签发阶段即被拒绝；回滚或新版本生效后，旧授权立即失效。

## 模块结构

| 模块 | 职责 |
| --- | --- |
| `app/units.py` | UCUM 单位子集与七维量纲分析（温度偏置、压力、转速、流量等） |
| `app/catalog.py` | 参数目录（量纲/范围/风险/依赖）与设备型号能力（原生单位、物理上下限） |
| `app/content.py` | 规范 JSON 序列化、SHA-256 摘要、不可变内容寻址存储 |
| `app/crypto.py` | 消息签名/验签（HS256），`alg`/`kid`/`sig` 原样保留 |
| `app/identity.py` | 人员与角色（工程师/审核人/质量负责人/管理员） |
| `app/recipe.py` | 草稿编辑、提交校验、技术复核与质量会签状态机 |
| `app/devices.py` | 模拟机器人控制器：验签指令、签名回执，可切换故障模式 |
| `app/release.py` | 冻结、分波下发、回执门控、暂停/重试/回滚、设备版本台账 |
| `app/authorization.py` | 开批授权令牌签发与闸门校验 |
| `app/audit.py` | 一次发布记录的全景视图（中文报告） |
| `app/platform.py` | 装配工厂 |
| `app/demo.py` | 全链路核验脚本 |

`domain_contract.json` 中的状态与本实现一一对应：

- 审核状态：`draft / technical_review / quality_review / approved / rejected`
- 发布状态：`frozen / deploying / paused / completed / rolled_back`
- 设备结果：`applied / digest_mismatch / timeout / rejected`

## 运行

```bash
# 56 个测试：单位换算、校验、审核、发布门控、回执、授权、回滚、审计视图
python -m unittest discover -s tests -v

# 五个端到端核验场景
python -m app.demo
```

`app.demo` 依次演示并打印：

1. 编辑校验拦截量纲错误 → 分级审核 → 分波发布 → 开批授权（含灰度外拒绝）；
2. **签名篡改**的回执被拒；设备侧摘要不一致 → 停止扩散，已生效设备保留版本；
3. **重复回执**被拒；
4. **灰度暂停**期间禁止扩散，恢复后完成；
5. 试点异常 **回滚**：旧发布置 `rolled_back`，新发布引用旧内容摘要只下发
   受影响设备，完成后全部设备回到同一旧版本。

## 关键设计说明

- **单位换算**：目录范围以基准单位表达；下发前按设备型号的原生单位换算
  （如 MIXER-X 真空压力收 `bar`，配方可用 `kPa` 编辑）。量纲不同直接拒绝，
  摄氏/华氏温度按带偏置仿射换算处理。
- **参数依赖**：支持必填、参数共现（`requires`）、条件依赖（真空搅拌必须
  给真空压力）、跨参数关系（烘干温度 < 固化温度）。
- **防重与防重放**：回执按 `receipt_id` 去重（同设备重复、跨设备复用均拒绝），
  且 `command_id` 必须与当前待回执指令一致，旧指令回执被拒。
- **局部失败**：波内一台失败只暂停扩散；成功设备版本标记不动；失败设备可在
  控制器修复后用新指令重试，失败清零方可 `resume`。
- **回滚不是覆盖**：内容库中所有版本仅追加；回滚发布通过 `rollback_of` /
  `restores_digest` 与原发布双向可追溯。
- **唯一适用版本**：同一设备×产品同时只允许一个活动标记；若出现多个不同
  摘要的活动版本，`active_version` 直接报错而非静默选择。
