# 工艺配方受控发布

本项目管理制造配方从编辑、复核到设备生效的受控过程。配方内容、审核签名和设备回执分别保存，发布记录使用内容摘要关联不可变版本。

`domain_contract.json` 列出审核、发布和设备应用状态。参数单位采用 UCUM 代码，外部消息中的签名算法与摘要值必须作为原始字段保留。

## 模块结构

| 模块 | 职责 |
| --- | --- |
| `app/units.py` | UCUM 单位注册表与量纲换算（温度含偏移量） |
| `app/catalog.py` | 参数目录：声明单位、允许范围、风险等级、参数间依赖规则 |
| `app/recipe.py` | 配方草稿：量纲/范围/依赖三层校验，规范化内容与内容摘要 |
| `app/signing.py` | 签名消息格式（HMAC-SHA256），算法与摘要作为原始字段保留 |
| `app/review.py` | 审核状态机：禁止自审，高风险参数须质量负责人会签，决定全部签名 |
| `app/devices.py` | 设备台账、能力校验、可编程故障的模拟设备网关 |
| `app/release.py` | 发布管理：冻结摘要 → 按组分批下发 → 失败停止扩散 / 灰度暂停 / 回滚 |
| `app/resolution.py` | 操作员开批前按（设备, 产品）解析唯一适用版本，过期授权与灰度外设备拒绝 |
| `app/reporting.py` | 发布记录报告：审核链、每台设备指令与回执、失败处置、当前适用范围 |

## 关键语义

- **编辑期**：录入单位与参数声明单位量纲必须一致；取值换算到声明单位后落在范围内；目录中的依赖规则（如冷却温度低于混合温度）全部成立。同一物理配方用等价单位录入会得到相同内容摘要。
- **审核**：`draft → technical_review → (quality_review) → approved / rejected`。审核人不能批准自己的变更；含高风险参数时技术审核通过后还须质量负责人会签，且会签人不同于技术审核人。每步决定签名绑定内容摘要。
- **发布**：冻结时先验签审核链再做设备能力校验，内容入库、记录只引用摘要。按设备组分批下发；回执缺失（超时）或摘要不一致时立即停止扩散（`paused`），已成功设备保留当前版本标记。重复回执幂等忽略，矛盾回执报错。
- **回滚**：创建一条引用旧内容摘要的新发布（`kind=rollback`），走同样的下发流程，全部生效后原发布才标记 `rolled_back`；任何记录都不被覆盖。
- **应用解析**：版本标记只由 `applied` 回执写入，（设备, 产品）天然唯一；设备不在灰度范围或授权窗口过期一律拒绝。

## 运行

基础检查与全部领域测试：

```bash
python3 -m unittest discover -s tests -v
```

全链路演示（含局部失败停止扩散与回滚，打印发布记录报告）：

```bash
python3 -m app.demo
```

测试覆盖的核验场景：签名篡改（审核决定与设备回执）、重复回执、灰度暂停与恢复、回滚引用旧内容、过期授权与灰度外设备拒绝、量纲/范围/依赖校验。
